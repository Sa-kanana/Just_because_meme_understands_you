# 共享用户账号与管理角色

## 账号与角色

普通用户和管理人员共用 `user` 与 `user_auth`。`role` 保存系统角色，`user_role` 负责账号与角色的多对多关联。系统内置 `USER`、`ADMIN`、`SUPER_ADMIN`：注册账号默认获得 `USER`；管理员可以同时持有 `USER` 与 `ADMIN`；超级管理员同时持有三种角色。

角色校验由 Spring Security 方法授权完成。管理端业务控制器统一位于 `/admin/v1/**`，并要求 `ADMIN` 或 `SUPER_ADMIN`。访问令牌携带角色列表；续签访问令牌时会重新读取数据库中的角色，使角色变更后不再续签旧权限。

## 登录入口

| 用途 | 请求 | 权限要求 |
| --- | --- | --- |
| 用户登录 | `POST /api/v1/auth/login` | 有效共享账号 |
| 管理端登录 | `POST /api/admin/v1/auth/login` | 账号必须持有 `ADMIN` 或 `SUPER_ADMIN` |

两个入口使用相同的账号密码和验证码校验。管理端登录还会检查管理角色；普通用户账号不能通过管理端入口登录。部署环境通过 `/api` 前缀暴露服务，Spring 控制器映射中的内部路径分别是 `/v1/**` 与 `/admin/v1/**`。

## 迁移与首个超级管理员

Flyway 迁移 `V2026100908__shared_user_roles.sql` 会创建角色表和关联表，把旧 `user.role` 逐项迁移到关联表后删除该单字段。旧管理员保留 `ADMIN`；未知或空角色以最低权限迁移为 `USER`。迁移不会自动挑选账号成为超级管理员。

首次部署需要先注册或确认一个共享用户账号，再设置环境变量 `AUTH_BOOTSTRAP_SUPER_ADMIN_EMAIL` 为该账号邮箱并启动后端。仅当数据库中还没有超级管理员时，引导程序才会为这个已有账号追加 `SUPER_ADMIN`，并保留它原有角色。邮箱未注册时后端会明确启动失败，避免悄悄以普通权限运行。成功初始化后可移除该环境变量。

## 账号保护

- 用户不能禁用自己，也不能修改自己的角色。
- 只有超级管理员可以授予或移除 `SUPER_ADMIN`，也可以修改另一个超级管理员。
- 不能禁用或降权最后一个超级管理员；检查在事务内锁定角色关联，串行处理并发修改。
- 账号禁用或角色变化会撤销该账号已有会话。

当前管理端提供账号状态和角色维护，没有删除用户的管理接口。若之后增加删除能力，必须同样拒绝删除操作者本人，并阻止删除最后一个超级管理员。
