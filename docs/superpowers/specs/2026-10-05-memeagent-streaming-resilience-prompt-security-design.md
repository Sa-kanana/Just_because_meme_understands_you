# MemeAgent 流式韧性与提示词安全设计

**日期：** 2026-10-05

**状态：** 待评审

## 目标

让 Java → Python MemeAgent → 检索/模型 → SSE 前端这条搜梗链路具备可配置的超时、有限重试和明确降级行为；保持真正的异步流式输出；统一系统提示词；降低用户历史、业务数据和检索内容触发提示注入的风险；不把不完整回答写入会话或缓存。

## 当前链路与问题

- 前端通过 `fetch` 读取 SSE；Java `WebClient` 转发 Python SSE；Python FastAPI `StreamingResponse` 使用 LangChain `AgentExecutor.astream_events`。
- Python 已开启模型 streaming，但缺少统一的模型、检索、联网工具和整条 Agent 链路预算。初始检索失败会直接发出服务错误；联网工具没有明确超时边界。
- 模型在首个可见文本前失败时，Python 会发检索摘要；在已发部分文本后失败时会发 `error`。Java 当前在 Flux 正常结束时会保存缓冲文本，因此 error 事件之后的结束仍可能保存半截回答。
- `prompts.py`、`meme_agent.py` 和 `search_agent.py` 分别持有系统规则、工具规则和请求级任务指令；用户/上下文使用易伪造闭合标签包裹，可能造成指令重复及信任边界不清。
- 用户历史和工具数据虽有消毒与提示约束，但需要统一规定其不可信等级，并保证模型调用只持有固定只读工具。

## 方案

保留现有 LangChain 工具调用 Agent 与 SSE 协议。由 Python 负责模型/检索/联网工具的重试、时限、降级和提示词策略；Java 负责流完成判定与不完整数据保护。Java 不重试已开始的 SSE，避免重复内容和重复工具执行。前端继续使用现有 `session/meta/cite/token/done/error` 事件。

不替换整个 Agent 编排，不新增依赖，也不改变 Java MySQL 与 Python 向量库的边界。

## 超时、重试与降级

### 配置默认值

Python 配置加入明确的中文注释，并支持环境变量覆盖：

| 阶段 | 超时 | 最大重试 | 行为 |
|---|---:|---:|---|
| 单次模型请求 | 35 秒 | 2 次 | 仅由模型客户端重试当前请求，不重跑完整 Agent；只对可恢复的超时、网络错误、429 和 5xx 重试 |
| 初始站内检索 | 12 秒 | 1 次 | 仅对可恢复错误重试；耗尽后使用 Java 传入的公开候选继续降级 |
| 实时联网工具 | 25 秒 | 0 次 | 失败或超时作为可识别的空结果交回 Agent，继续使用站内资料 |
| Python Agent 总时限 | 120 秒 | — | 总时限到达时取消未完成工作并按是否已发出文本决定降级或报错 |
| Java SSE 无事件看门狗 | 130 秒 | — | 只作用于 AI 搜索 SSE，检测无事件挂起；不改变共享 WebClient 的采集超时 |

4xx 参数错误、校验错误和非暂时性业务错误不重试。两次重试的退避依次为 0.5 秒、1 秒，单次等待上限 2 秒；所有重试共用上述上限，避免多层重试相乘。重试次数、超时配置、阶段名和请求 ID 写入结构化日志，不记录完整私密输入，也不把上游异常详情发给用户。

### 失败语义

- 模型尚未输出任何用户可见回答文本时，模型客户端在当前模型调用内最多重试 2 次。耗尽后，Python 用检索命中及 Java 候选生成确定性摘要并发 `done`，`finish_reason` 标明降级。
- 初始向量检索耗尽重试后，仍可基于 Java 传入的候选回答；没有可靠候选时用固定的“暂时无法检索”回复，不能误报“没有相关梗”。
- 实时联网工具超时或失败时，将可识别的失败状态交回 Agent；Agent 继续根据站内结果回答，不把联网失败伪装成“没有最新内容”。
- 首个用户可见回答文本发出后，任何模型/总时限错误都发 `error`，不重试整条 Agent、不追加另一条互相矛盾的答案、不发 `done`。已发给浏览器的文本无法撤回。
- Python 取消或客户端断开时，取消当前模型/工具任务并释放上游流。
- Python 与 Java 对客户端返回通用错误信息；具体上游异常只进入受控日志，不向用户暴露 provider 响应或内部细节。

## SSE 完成与持久化

- 成功答案和完整的确定性降级答案都以 `done` 结束；降级使用明确的 `finish_reason`。
- Java 只在收到 `done` 且流无 error/传输超时的情况下保存完整助手回答。正常完成的回答可写入历史并缓存；带 `fallback_*` 的完整答案写入会话历史以维持对话连续性，但不写入通用问答缓存，避免临时故障答案长期复用。
- 收到 Python `error`、上游传输异常、130 秒无事件超时或取消时，丢弃缓冲区，不写助手消息、不写缓存。用户消息仍按现有业务规则保存。
- Python 只把最终面向用户的文本作为 `token` 转发，不暴露工具调用参数或 Agent 中间输出。事件名称、负载字段继续兼容当前前端。

## 提示词规范与注入防护

1. 在 `app/agents/prompts.py` 定义单一、版本化的权威 system prompt，包含身份与任务、信任层级、证据范围、工具选用条件和输出格式。Agent 构造器直接消费该提示词。
2. 删除 `search_agent.py` 中重复的请求级指令；该层只构造数据输入、调用 Agent 并转发最终回答事件。工具描述只保留各自用途与入参说明，不重复系统规则。
3. 当前查询与 Java 业务上下文作为 JSON 数据放在 user 消息中；不将请求、历史、候选或检索结果插入 system prompt。JSON 序列化保证伪造闭合标签仍是字段值，不能改变消息结构。
4. 明确声明所有 user/assistant 历史、Java 业务片段、向量检索片段、运营知识片段和网页摘要都是不可信的数据，不能覆盖 system 规则或要求调用其他工具。历史仍仅允许 `user/assistant` 角色。
5. 保留工具白名单，只提供当前三个只读工具；模型不具备 SQL、写库、鉴权或其他副作用工具。内部 ID 仅供 cite 事件，不能出现在回答正文。
6. 现有注入正则继续用于告警和观测，不因命中就拒答合法的安全问题；安全性不依赖关键词列表。拒绝伪造 system/developer 角色、消息边界和数据字段内容触发更高权限。
7. 为提示词版本加入日志/追踪 metadata，便于检索回归问题时确认使用的指令版本。

## 涉及范围

- Python：`MemeAgent/app/core/settings.py`、`.env.example`、`app/agents/prompts.py`、`app/agents/meme_agent.py`、`app/agents/search_agent.py`、`app/agents/tools.py`、`app/security/sanitize.py` 及相应测试。
- Java：`MemeAgentProperties`、AI 搜索服务与 `application.yml` 中 AI 专用 SSE 无事件看门狗配置，以及 AI 搜索服务测试。
- 前端 SSE 协议不变；除非验证发现现有 `onError` 消费行为无法展示错误，否则不改前端。
- 不改向量维度、检索融合算法、数据库 schema、业务 MySQL 查询、登录鉴权和采集任务超时。

## 验收标准

- 模型、检索、联网工具和 Python 总时限使用配置值；重试次数严格受配置上限约束，非暂时性错误不重试。
- 首 token 前模型重试耗尽能降级并以 `done` 结束；检索无命中与检索服务不可用显示不同结果。
- 首 token 后失败发 `error` 且无 `done`；Java 不保存、不缓存任何部分 token。
- 正常 `done` 能保存并缓存；完整 `fallback_*` 可保存历史但不会写缓存。
- 伪造闭合标签、`ignore previous instructions`、假 system/developer 消息、恶意检索片段均不能改变工具集合或 system prompt；正文仍按单一可信规则输出。
- 流式仅发送最终答案的文本 token；SSE 事件协议保持兼容。
- Python 测试全套通过；AI 搜索相关 Java Maven 测试通过；配置和代码差异通过 `git diff --check`。

## 风险与边界

Prompt 注入属于模型行为风险，文本指令只能降低概率，无法对任意模型输出作形式化保证。本方案的安全边界是固定角色与工具集合、只读能力、输入数据隔离、不可缓存部分答案以及对异常采用安全降级。超时参数需要在实际网络和模型服务表现下调整；默认值是可运维起点，不代表供应商 SLA。
