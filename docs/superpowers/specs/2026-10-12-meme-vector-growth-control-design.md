# Meme 向量库增长治理设计

## 目标

控制 `meme_vector_chunk` 的非预期膨胀，清除与 Java 业务库状态不一致的孤儿向量，同时保留仍有效的旧梗。梗向量不使用按创建时间或更新时间自动过期的 TTL。

## 当前问题

1. `meme_vector_chunk` 没有自动保留期限；正常更新会事务性替换旧分块，相同 `content_hash` 会跳过 embedding，删除/下架事件会删除对应向量。
2. `MAX_CHUNKS_PER_MEME = 6` 当前用于检索候选数估算，不限制入库分块数。
3. 入库将标题和标签前缀重复写入每个正文分块。标签限制了数量但未限制单项或累计长度；当前 chunker 在前缀过长时会将正文分块宽度压到 1 个字符，最多可为一条 5000 字介绍创建数千个重复前缀向量。
4. Java outbox 负责正常索引事件，但长期运行仍需要定期清理漏投、最终失败或历史遗留的无效梗向量。

## 设计

### 1. 入库内容与分块上限

- 保留标题最多 200 字、介绍最多 5000 字、标签最多 20 项。
- 每个标签最多 64 字，标签去空白后的累计长度最多 240 字；超限由请求校验拒绝，不静默截断。
- 将 `MAX_CHUNKS_PER_MEME = 6` 放入共享限制模块，让检索候选计算与入库分块共用同一值。
- chunker 在调用 embedding 前确保输出不超过 6 块。第一块保留标题与标签，后续块重复短标题前缀，不再重复标签；保持默认每块不超过 1200 字。
- 若未来修改分块规则导致合法字段仍产生超过 6 块，明确拒绝该文档并记录梗 ID、实际块数和上限，不生成 embedding、不写入半成品。

### 2. 定期清理孤儿向量

Java 业务库仍是梗的有效状态唯一来源；现有 outbox 保持新增、修改、下架和永久删除的主同步路径。增加一个每日运行的内部 reconciliation job，按批扫描 pgvector 中已有的梗 ID，只删除业务库中不存在或状态不是已发布的向量，不按年龄删除有效梗，也不恢复被移除的手动回填入口。

接口与步骤：

1. MemeAgent 提供仅内部写密钥可访问的游标分页接口，按 `meme_id` 排序返回一页向量摘要：`meme_id`、`content_hash`、`updated_at`。默认每页 500 个梗 ID，响应还包含下一游标。
2. Java job 对当前页的 ID 批量查询业务库，只把不存在或非公开的 ID 交给条件删除接口。
3. Python 仅在 `meme_id + content_hash + updated_at` 与扫描快照仍一致时删除该梗的所有 chunk。这样 outbox 在扫描后写入了新版本时，旧清理请求不能删掉新版本。
4. 对同 hash 的幂等 upsert 不再直接返回：先在 PostgreSQL 原子刷新该梗所有 chunk 的索引更新时间；若刷新时记录已被条件删除，则按正常流程重新生成向量并写入。该行为与条件删除共同覆盖扫描与写入并发。
5. 任一页或删除批次失败时停止本轮并记录失败；下次从头扫描。操作幂等，不持久化页游标，也不做部分进度确认。

任务默认每 24 小时运行一次，分页大小默认 500，并允许通过带中文注释的配置项调整。日志只记录扫描数、无效候选数、实际删除数、条件冲突跳过数、耗时和失败阶段，不记录正文、标签或 embedding。

### 3. 容量观测与 PostgreSQL 清理

新增只读 SQL 运维脚本，展示梗数、chunk 数、每梗最大/平均 chunk 数、表与索引总大小、HNSW 索引大小及 dead tuple/最近 autovacuum 信息。PostgreSQL autovacuum 负责回收删除产生的 dead tuple 以供复用；不自动执行会长时间锁表的 `VACUUM FULL`。只有指标显示 HNSW 膨胀时，运维手动评估 `REINDEX INDEX CONCURRENTLY`。

## API 与兼容性

- 现有 `/ingest`、`/ingest/delete` 和 Java outbox 语义保持不变。
- 新增的候选分页、条件删除端点只供 Java 内部任务调用，复用 `WriteAuth`，不开放给浏览器或普通用户。
- 新接口只按 pgvector ID 和版本摘要传输，不传业务正文；Java 用数据库批量状态查询，不把整个梗库一次性载入内存。
- 不改向量表数据模型，不新增 SQL 表或字段；如实现时发现必须新增 DDL，所有列都补中文 `COMMENT`，并提供可回滚迁移。
- 尊重当前工作区的未提交修改；不恢复其正在移除的手动 backfill API。

## 验收条件

1. 超长单标签、累计超长标签在请求校验阶段失败。
2. 接近字段上限的有效梗最多生成 6 个 chunk；chunker 永远不会因长前缀将正文宽度退化为 1 字。
3. 超过分块上限时 embedding 调用次数为 0，向量表不产生部分写入。
4. 分页按稳定游标返回无重复/漏页的 ID；仅删除业务库不存在或非公开的梗。
5. 新版本在扫描后 upsert 时，条件删除跳过该新版本；相同 hash 重放会更新同步时间，删除与重放并发不会造成向量永久丢失。
6. job/API 失败会写出可定位阶段的日志，并在下一轮可重新从头执行。
7. 容量脚本可在当前 PostgreSQL/pgvector 环境执行并输出表、索引和 vacuum 统计。
8. Python 与 Java 相关单测通过；不执行真实向量删除或 embedding API 调用。

## 不包含

- 对有效梗按年龄做 TTL。
- 对有效梗进行自动摘要或静默截断。
- 改变管理员知识库保留、清理或检查点 TTL。
- 自动重建全部缺失的已发布向量；新增任务只清理无效/孤儿向量，新增和更新继续依赖现有 outbox。
