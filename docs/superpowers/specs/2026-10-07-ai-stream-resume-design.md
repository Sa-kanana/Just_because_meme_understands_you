# AI 流式任务脱离浏览器并可恢复设计

日期：2026-10-07
状态：待用户审阅
范围：Java 后端、Vue 前端、Redis；MemeAgent 继续提供现有生成流

## 目标

AI 搜索任务由 Java 后端托管，不再依赖某个浏览器请求的生命周期。切换标签页、离开 AI 搜索页、刷新、断网或关闭浏览器时，生成继续；重新进入时可以恢复事件流。只有用户显式点击“停止生成”或任务达到 TTL，才取消上游生成。只有收到 `done` 事件后才持久化完整回答并写答案缓存。

用户确认的生命周期：

| 场景 | 行为 |
| --- | --- |
| 切换浏览器标签页 | 后台继续 |
| AI 搜索页跳转到其他页面 | 后台继续 |
| 返回 AI 搜索页 | 找回任务并恢复流 |
| 网络暂时断开 | 后台继续，前端自动重连 |
| F5 刷新 | 后台继续，页面重新查找任务并恢复 |
| 关闭浏览器 | 后台继续，完成后保存完整答案 |
| 点击“停止生成” | 显式取消任务 |
| 创建任务满 10 分钟 | 取消生成并清理任务和事件 |

## 已确认的设计决策

- Java 是任务生命周期、用户身份和会话归属的权威层；Python MemeAgent 继续只负责执行 AI 搜索并输出现有 SSE 事件。
- 任务状态和可回放事件存入 Redis；会话及完整问答继续以 MySQL 为准，不增加任务数据库表。
- 每个用户同一时间最多有一个运行中的 AI 任务。任务仍运行时再次提交不同请求返回冲突；相同 `requestId` 的重试返回同一任务。
- 任务 TTL 从创建时开始计时，固定默认 10 分钟。Redis 状态与事件在该期限到达时过期；Java 任务计时器同时取消其上游订阅。
- 浏览器连接只负责读取事件。断开浏览器订阅不会取消 Java 后台订阅；停止按钮调用独立取消接口。
- Java 服务进程重启后的任务续跑不在本次范围内。进程退出会中断本机上游订阅；Redis 中的任务数据仍会按 TTL 自动过期。

## 架构与数据流

1. 前端提交问题，Java 验证用户、请求参数和现有会话归属，按用户与 `requestId` 做幂等登记，并建立任务及 TTL。
2. Java 立即启动独立于 HTTP/SSE 订阅请求的 MemeAgent 消费流程。该流程持有自己的 Reactor `Disposable`，并把 Python 事件写入 Redis 事件流。
3. Java 返回 `taskId`、`sessionId`、`requestId` 和过期时间。浏览器随后通过单独的 SSE 事件接口读取 Redis 中的历史事件和新事件。
4. SSE 事件使用单调递增的事件 ID。前端保留最后一个已处理 ID；断线重连时从该 ID 之后恢复，避免重复追加 token。
5. 前端每次进入 AI 搜索页先查询当前用户任务。若任务运行中则加载对应会话并重新订阅；若任务已完成则重新加载 MySQL 消息；若任务已失败或取消则恢复其终态信息。
6. 后端收到 Python `done` 后保存完整 assistant 消息并按现有规则写答案缓存。流错误、用户取消、TTL 结束和无 `done` 的提前结束都不保存部分 assistant 答案。

Redis 为每个任务保存任务元数据和有序事件流，并设置相同的到期时间。元数据至少包含任务 ID、用户 ID、会话 ID、请求 ID、状态、创建时间和到期时间。用户当前任务指针及请求幂等映射也有 TTL。不得将问题正文写入日志；任务事件只在其 TTL 内保留。

任务状态包括 `RUNNING`、`COMPLETED`、`FAILED`、`CANCELLED` 和 `EXPIRED`。不同 Java 实例通过共享 Redis 读任务与事件；任务创建使用原子登记避免重复启动。取消请求通过 Redisson Redis Pub/Sub 通知持有上游订阅的实例。SSE 读取从共享 Redis 事件流按游标回放，因此可由任一实例处理。

状态从 `RUNNING` 到任一终态只允许原子转换一次：收到 `done` 转为 `COMPLETED`，上游错误转为 `FAILED`，用户取消转为 `CANCELLED`，到期转为 `EXPIRED`。竞争时第一个成功的状态转换生效；终态不会被迟到的取消、到期或完成事件覆盖。重复取消请求返回现有状态。

## HTTP 接口

所有接口都要求现有登录态。后端从认证上下文获取 `userId`，不信任请求体中的用户 ID。读取、恢复、取消任务时校验任务归属。

### 创建任务

`POST /v1/ai/searches`

保留现有 `query`、可选 `sessionId` 和 `requestId` 请求字段。响应改为 JSON，返回 `taskId`、`sessionId`、`requestId`、状态及 `expiresAt`。相同用户以相同 `requestId` 重试时返回原任务，不重复保存用户消息或再次调用模型；不同请求遇到该用户已有运行任务时返回冲突。

### 查找当前任务

`GET /v1/ai/searches/current`

返回当前用户 TTL 内最新任务及状态；无任务时返回空任务。此接口供页面刷新和重新进入时恢复任务，不能通过传入其他用户 ID 查询。

### 回放与订阅事件

`GET /v1/ai/searches/{taskId}/events?after={eventId}`

返回 SSE。保留当前 `session`、`meta`、`cite`、`token`、`done`、`error` 事件名和 data 结构，只增加标准 SSE `id`。服务端先回放 `after` 之后的 Redis 事件，再持续读取新事件；任务终态后关闭响应。任务已过期或不存在时返回明确的过期/未找到结果。

### 显式取消

`POST /v1/ai/searches/{taskId}/cancel`

校验当前用户拥有该任务，再发布取消信号并释放上游订阅。取消不会保存已生成的部分答案。页面离开或 SSE 连接断开不得调用此接口。

## 前端行为

- `AiSearch.vue` 卸载时只停止浏览器 SSE 读取，不取消后端任务。
- Pinia 保存当前任务 ID、会话 ID、最后事件 ID 和已收的临时 assistant 内容。刷新后从当前任务接口重建临时消息；无游标时从事件流开头重放。
- 网络断开后按有上限的退避间隔自动重连，持续到任务终态或任务 TTL。
- “停止生成”按钮调用取消接口，然后停止 SSE 订阅并显示已取消状态。
- 若同一用户已有其他运行中的任务，提交按钮显示明确提示，允许等待当前任务结束或显式停止后再提交。
- 任务完成后从 MySQL 重新加载消息，确保页面最终展示与持久化内容一致。

## 用户可见回答与诊断日志

- AI 回答只提供与问题相关且有来源支持的结论和结果，不叙述检索过程、查询过的来源、命中数量、工具调用、等待、重试、降级或后台状态。没有任何可用证据时只回复“不知道。”，不得补充无来源的背景解释、建议或其它兜底话术。
- 后端日志可以记录检索和生成的阶段、状态、耗时、命中数量、重试次数、降级类型及错误类别，便于诊断整条链路；不得记录原始用户问题、完整检索正文或模型内部思维链。
- 修改托管系统提示后，同步升级 Python `PROMPT_VERSION` 与 Java 答案缓存流水线版本，避免旧答案缓存掩盖新输出规范。

## 错误处理、安全与清理

- 继续使用现有 Python 错误净化及 Java SSE 错误结构，不向前端暴露模型提供商的内部错误细节。
- 用户取消、上游错误和 TTL 结束均释放 Java 到 Python 的订阅；任务状态进入对应终态，部分文本不进入 MySQL 或答案缓存。
- Redis 任务状态、事件流、用户任务指针和幂等记录使用配置的 10 分钟 TTL 自动清理。新增配置项和代码字段需有清晰中文注释。
- 删除会话时应一并取消该会话尚未完成的任务，防止软删除会话后仍写入回答。
- 不保证 Java 进程崩溃或部署重启后的任务恢复；这不影响浏览器断开、刷新或关闭时后端进程仍运行的目标。

## 验收与验证

- 切页、刷新和断开 SSE 后，Java 到 Python 的任务仍继续，之后可按事件 ID 恢复且不重复 token。
- 浏览器关闭后，任务可完成并将完整回答写入会话；未收到 `done` 时不会保存部分回答或缓存。
- 停止接口能取消上游生成；10 分钟期限能取消上游并清理 Redis 任务及事件。
- 重复 `requestId` 不重复创建任务、保存用户消息或调用 Python；同一用户不同任务并发会被拒绝。
- 未拥有任务的用户不能查询、恢复或取消任务；所有 SSE 事件仍使用既有协议。
- 验证范围包括 Java 任务生命周期与权限、Redis 回放/TTL、前端重连与停止行为，并覆盖断网、F5 和关闭浏览器后重新进入的流程。

## 本次不包含

- Java 服务进程重启后的任务执行恢复。
- Python MemeAgent 新增任务 API、队列或数据库。
- 同一用户并行运行多个 AI 任务。
- 更改检索算法、SSE 事件名称或 MySQL 会话表结构。
